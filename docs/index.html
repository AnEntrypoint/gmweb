gmweb

A Linux desktop in the browser, packaged as one container. Open a URL, log in once, and get the XFCE desktop, a web terminal, a file manager, and AgentGUI for running Claude Code and OpenCode agents.

Source on GitHub · Readme · docker-compose.yaml

What you get

Desktop /desk/

The live XFCE session, streamed to the browser by Selkies.

Terminal /ssh/

A shell in the browser, served by webssh2 on ttyd.

Files /files/

A web file browser rooted at /config/Desktop.

Agents /gm/

AgentGUI: a chat UI for Claude Code and OpenCode sessions.

Logs /logs/

Plain-text listing of the boot and service logs.

One password

Every route is behind HTTP Basic Auth using the PASSWORD you set.

The stack

gmweb is a layer on top of projects that already exist. Each row below is an upstream project, what it does, and what gmweb does with it.

What gmweb adds on top

Supervisor

startup/index.js loads the services listed in startup/config.json, groups them by dependency, and restarts any that fail a health check.

Boot script

docker/custom_startup.sh prepares nginx, permissions, Node.js and npm caches, then starts the supervisor. Slow installs run in the background so they never block startup.

Fresh code every boot

On each start the container clones this repo from main, so a push reaches the next restart without rebuilding the image.

One credential

PASSWORD generates the nginx Basic Auth file and is passed to every service that needs it.

Two persistent volumes

/config holds user data and service state. /usr/local keeps installed tools across restarts.

Two images

The desktop image (Dockerfile) and a headless image (Dockerfile.headless, no desktop) for terminal, files and agents only.

How it runs in Coolify

The Compose file is the deployment. Coolify reads it, routes HTTPS through Traefik, and runs one container.

Steps

  1. In Coolify, create a resource from the repo's docker-compose.yaml, or from the published image almagest/gmweb:latest.
  2. Set PASSWORD. Leave the default and every route is open to anyone who knows password.
  3. Make sure Traefik's file provider defines the gmweb-h1@file transport. The compose labels reference it.
  4. Deploy. The container port is 80; Coolify maps the domain to it through the labels.
  5. Open https://<your-domain>/desk/ and log in as abc.

Ports and networking

PortProtocolPurpose
80 / 443TCPnginx: the whole web UI (through Traefik in Coolify)
59000UDPSelkies WebRTC media. Optional: if blocked, the desktop falls back to WebSockets on 443

Transport choice

Selkies runs one transport at a time. SELKIES_MODE=webrtc is the default: media goes straight from the container to the browser over UDP, which is fastest when the network allows it. websockets sends the same stream over the HTTPS connection that is already open, so it works from any network that can reach 443. With SELKIES_ENABLE_DUAL_MODE=true, an operator can switch with POST /desk/api/switch.

Behind a 1:1 NAT, set SELKIES_WEBRTC_PUBLIC_IP to the host's public address, or leave it blank for autodetection at boot. Otherwise the browser is offered the container's private IP, which it cannot reach. For WebRTC through a firewall that forwards no UDP, see the notes in CLAUDE.md.

Run it locally

cp .env.example .env
docker compose up -d --build

Set PASSWORD in .env, then open https://localhost/ (accept the self-signed certificate) and log in as abc.
