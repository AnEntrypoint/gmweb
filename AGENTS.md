# Operational facts

- Native browser WebSocket handshakes cannot supply the site HTTP Basic credentials. The `/sync` and `/gm/sync` Nginx locations therefore disable Basic auth while preserving their AgentGUI upstream and upgrade routing.
- The Compose service references `gmweb-h1@file`; deployment must provide that Traefik transport through its file provider.
- Only `99-gmweb-startup.sh` is executable in `/custom-cont-init.d`; it invokes the non-executable helper scripts so s6 does not start them independently.
- Selkies serves one transport at a time and the client follows the server's mode, so `SELKIES_MODE` must name a transport the network can actually carry.
- Selkies advertises the container's own IP (e.g. `10.0.2.2`) in its WebRTC host candidates unless `SELKIES_WEBRTC_PUBLIC_IP` names a reachable address; clients cannot route to the container IP, so ICE never completes. The setting maps through NAT1TO1 onto the UDP-mux candidate, and `svc-selkies/run` autodetects the public IP when it is blank.
- s6 runs each service from a copy under `/run/service/<name>/`, made at boot; editing `/etc/s6-overlay/s6-rc.d/<name>/run` in a *live* container changes nothing until the container restarts. Edit the `/run/service/` copy to change a running service, and the `/etc` one to change what the next boot starts.
- Selkies' WebRTC routes live under the API prefix: `/api/websockets` for the data socket and `/api/ws` for WebRTC signalling. The `^~ /desk/websocket` Nginx location is vestigial — it proxies to `http://127.0.0.1:8082/`, which strips the path entirely, so it is served by the SPA rather than reaching Selkies. The working path is `/desk/api/websockets` through the `/desk/api/` location.
- WebRTC needs full ICE (`SELKIES_WEBRTC_ICE_LITE=false`) whenever the edge firewall forwards no UDP rule. The SonicWALL in front of boxone maps UDP with the source port preserved and independently of destination (measured against four separate STUN servers), so inbound UDP is admitted by a mapping the host opens by sending first. An ICE-lite server never sends, so it never opens the mapping and the client sits at "connecting". It has no UPnP IGD and no NAT-PMP, so a mapping cannot be programmed automatically.
- `docker/rest-of-startup.sh` fetches the `startup/` tree from `STARTUP_REF` (default `main`) at boot. It previously pinned a frozen commit hash, which silently froze every service under `startup/` at that revision while the image itself kept tracking `main` — so a push updated the image but not the services.
- Selkies can be verified end to end on this host with a headless Chromium driving the real page (playwright tree at `/config/workspace/zellous/node_modules`, run inside the container). It logs `[webrtc] Connection complete` and streams video once the `Play Stream` affordance is clicked; before that click the video element stays `paused`, which is the autoplay policy, not a fault. That covers the LAN path — the client runs inside this host — so it does not prove the firewall crossing.
